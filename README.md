# 교육사진 자동 숏폼 제작 파이프라인

사진 폴더와 활동 설명 한 줄을 넣으면 **얼굴을 가린 9:16 세로 mp4**(1080x1920)를 만들어 줍니다.
유튜브 숏폼 규격에 맞춰 15~20초 길이로 출력합니다.

현재 구현 범위는 **Phase 1 (MVP)** 입니다. 전체 로드맵은 [docs/DESIGN.md](docs/DESIGN.md)를 보세요.

```
사진 폴더 ─▶ 얼굴 블러 ─▶ 자막 계획 ─▶ 켄 번즈 편집 ─▶ BGM 합성 ─▶ mp4
  (입력)     mediapipe      템플릿        moviepy       numpy/scipy    ffmpeg
                 │                                                       │
                 └──────────▶ review_sheet.jpg (사람이 검수) ◀───────────┘
```

## 설치

### 윈도우 USB 설치 (학교 컴퓨터용)

컴퓨터에 아무것도 설치하지 않고 USB 에서 바로 쓰는 방법입니다. 설치 권한이 막힌
학교 컴퓨터에서도 동작합니다.

1. 이 저장소를 ZIP 으로 내려받아 USB 에 풀어 넣습니다.
2. **폴더를 `G:\shorts` 처럼 짧고 단순한 경로로 옮깁니다.**
   대괄호(`[ ]`)가 들어가거나 경로가 길면 설치가 실패합니다. 압축을 풀면 폴더가
   두 겹으로 들어가는 경우가 많으니 안쪽 폴더만 꺼내세요.
3. `usb\setup.bat` 을 더블클릭합니다.
4. 10~30분 기다립니다. 인터넷이 되는 곳에서 하세요.

설치가 끝나면 USB 에 실행 파일 세 개가 생깁니다.

| 파일 | 하는 일 |
| --- | --- |
| `watch_start.bat` | 폴더 감시를 켭니다. 사진만 넣으면 알아서 만듭니다 |
| `make_one.bat` | 한 편씩 물어보며 만듭니다 |
| `check_only.bat` | 무엇이 만들어질지 미리 봅니다 |

자세한 사용법은 `usb/README.txt` 에 있습니다. 설치에 실패하면 `setup_log.txt` 가
생기니 그 파일을 확인하세요.

> **주의**: 이 설치 스크립트는 리눅스에서 만들어져 윈도우에서 검증되지 않았습니다.
> 문제가 생기면 `setup_log.txt` 와 화면 메시지를 남겨 주세요.

### 직접 설치 (맥·리눅스, 또는 파이썬이 이미 있는 윈도우)


```bash
pip install -r requirements.txt
python scripts/download_models.py    # 사람 검출 모델 (강력 권장)
```

**용량 주의**: 기본 설치는 약 4.7GB 입니다. 그중 3.2GB 가 쓰지 않는 GPU 라이브러리입니다.
CPU 전용으로 받으면 1GB 정도로 줄어듭니다.

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

USB 설치 스크립트는 이미 CPU 전용으로 받습니다.

`download_models.py` 는 인터넷 연결이 한 번 필요합니다. 건너뛰면 얼굴 전용 감지기로
동작하는데, 교실 사진에서는 누락이 크게 늘어납니다.

ffmpeg 은 `imageio-ffmpeg` 가 함께 설치하므로 따로 준비하지 않아도 됩니다.

한글 자막을 쓰려면 한글 폰트가 하나 필요합니다. 윈도우(맑은 고딕)·맥(Apple SD Gothic)에는
기본 설치돼 있고, 리눅스라면 아래처럼 설치하거나 `--font` 로 직접 지정하세요.

```bash
sudo apt install fonts-nanum        # 또는 fonts-noto-cjk
python make_shorts.py ... --font /path/to/NanumGothicBold.ttf
```

## 사용법

```bash
python make_shorts.py ./photos/과학실험 \
    -d "3학년 과학 시간, 화산 폭발 실험을 했어요" \
    -o output/volcano.mp4
```

빠르게 확인만 하고 싶으면 `--preview` (540x960, 저화질)를 붙이세요. 약 15초면 끝납니다.

### 주요 옵션

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `-d, --description` | 활동 설명 한 줄. 제목과 첫 자막에 쓰입니다 | (필수) |
| `-o, --output` | 출력 mp4 경로 | `output/<폴더명>.mp4` |
| `--title` | 상단 제목 직접 지정 | 설명에서 자동 생성 |
| `--captions` | 장면별 자막 JSON 직접 지정 | 템플릿 자동 생성 |
| `--ai-captions` | Claude 가 사진을 보고 자막 생성 | 꺼짐 |
| `--duration` | 영상 길이(초) | `18` |
| `--max-photos` | 사용할 최대 사진 수 | `8` |
| `--bgm` | `bright` / `calm` / `energetic` | `bright` |
| `--detector` | `auto` / `mediapipe` / `yunet` / `haar` | `auto` |
| `--blur-method` | `pixelate` / `gaussian` | `pixelate` |
| `--faces-json` | 놓친 얼굴 좌표를 직접 지정 | 없음 |
| `--keep-faces` | 블러를 적용하지 않을 사진 (예: 본인 사진) | 없음 |
| `--tight` | 차단 영역을 좁혀 보기 좋게 함 (누락 위험 증가) | 꺼짐 |
| `--verify` | 직접 블러한 사진을 검사만 함 (블러 재적용 안 함) | 꺼짐 |
| `--preview` | 540x960 저화질 빠른 확인 | 꺼짐 |
| `--seed` | 효과·BGM 변주 시드 | `0` |

### 자동 자막 (`--ai-captions`)

기본 템플릿은 "오늘도 한 뼘 더 성장" 같은 고정 문구를 돌려씁니다. `--ai-captions` 를
붙이면 Claude 가 사진을 직접 보고 활동에 맞는 제목과 자막을 씁니다.

```bash
export ANTHROPIC_API_KEY=sk-ant-...    # https://console.anthropic.com 에서 발급
pip install anthropic
python make_shorts.py ./photos/수업 -d "26년 관광 채용트렌드 수업" --ai-captions
```

**원본 사진은 전송되지 않습니다.** 블러 단계를 마친 결과물만 보냅니다. 전송 전에 긴 변
768px 로 줄이는데, 화질이 아니라 내용 파악이 목적이고 이미지가 비용의 대부분이기
때문입니다. 영상 한 편당 대략 $0.05 입니다.

생성된 자막은 학교명·학년·반이 들어갔는지 후처리로 한 번 더 걸러냅니다. 프롬프트에도
금지를 적지만 생성형이라 규칙만으로는 보장되지 않습니다. 걸린 항목은 실행 결과에
경고로 알려 줍니다.

**실패해도 영상은 나옵니다.** API 키가 없거나 호출이 실패하면 기본 템플릿으로 되돌아가고
그 사실을 경고로 남깁니다. 자막이 밋밋한 것은 불편이지만 영상이 안 나오는 것은 실패이기
때문입니다.

비용이나 품질을 조절하려면 `--ai-effort` 를 쓰세요 (`low` ~ `max`, 기본 `medium`).

> **사실관계는 사람이 확인하세요.** 사진만 보고 쓴 문구라 활동 내용을 잘못 짚을 수
> 있습니다. 완성된 `captions.json` 을 한 번 읽어 보시고, 고칠 것이 있으면 그 파일을
> 수정해 `--captions` 로 다시 넘기면 됩니다.

### 출력물

```
output/volcano.mp4              ← 완성본
output/volcano_work/
├── blurred/                    ← 얼굴을 가린 사진들
├── review_sheet.jpg            ← 검수용 격자 이미지 (초록 박스 = 가린 위치)
├── captions.json               ← 사용된 제목/자막
├── bgm_bright.wav              ← 합성된 BGM
└── report.json                 ← 실행 요약(사진 수, 감지 얼굴 수, 경고)
```

## 폴더 감시 자동 실행 (`watch_shorts.py`)

사진만 폴더에 넣으면 명령어를 치지 않아도 영상이 만들어집니다.

```
watch/
├── 과학실험/            ← 영상 한 편이 됩니다
│   ├── 1.jpg
│   ├── 2.jpg
│   └── description.txt  (선택: 활동 설명. 없으면 폴더명을 씁니다)
└── 운동회/
```

```bash
# 계속 감시 (학기 중 켜 두기)
python watch_shorts.py ./watch -o ./output

# 한 번만 훑기 (작업 스케줄러나 cron 에 등록)
python watch_shorts.py ./watch -o ./output --once

# 무엇을 처리할지 미리 보기
python watch_shorts.py ./watch -o ./output --dry-run
```

**결과는 `output/` 에 저장되고 거기서 끝납니다.** 유튜브에 자동으로 올라가지 않습니다.
얼굴 블러는 완벽하지 않고 자막은 생성형이라, 사람이 보지 않은 영상이 채널에 올라가면
안 되기 때문입니다.

### 복사 중인 폴더는 건드리지 않습니다

사진 여덟 장을 복사하는 중에 실행되면 일부만 들어간 영상이 나옵니다. 그래서 **가장
최근에 수정된 파일이 3분 이상 조용해야** 처리를 시작합니다. `--quiet-seconds` 로
조절할 수 있습니다.

### 같은 폴더를 두 번 만들지 않습니다

처리한 폴더는 `output/.watch_state.json` 에 기록됩니다. 다시 실행해도 건너뜁니다.
실패한 폴더도 자동으로 재시도하지 않습니다. 같은 사진으로 다시 돌리면 같은 결과일
가능성이 크기 때문입니다. 다시 만들려면 `--reprocess` 를 쓰세요.

### 주요 옵션

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `--once` | 한 번만 훑고 종료 (cron 용) | 계속 감시 |
| `--poll` | 확인 주기(초) | `60` |
| `--quiet-seconds` | 이만큼 조용하면 복사가 끝났다고 판단 | `180` |
| `--min-photos` | 영상을 만들 최소 사진 수 | `2` |
| `--reprocess` | 이미 처리했거나 실패한 폴더도 다시 만듦 | 꺼짐 |
| `--dry-run` | 무엇을 처리할지 보여주기만 함 | 꺼짐 |

영상 설정(`--duration`, `--bgm`, `--ai-captions`, `--detector` 등)은 `make_shorts.py`
와 같습니다.

### 왜 파일시스템 이벤트가 아니라 폴링인가

원래 설계는 `watchdog`(inotify/FSEvents)이었는데 폴링으로 바꿨습니다.

학교에서는 사진이 네트워크 드라이브나 클라우드 동기화 폴더(OneDrive, 구글 드라이브)에
올라옵니다. 이런 곳에서는 파일시스템 이벤트가 안 오거나 늦게 옵니다. **이벤트를 놓치면
영상이 영영 안 만들어집니다.** 게다가 이벤트를 받아도 복사가 끝났는지는 알 수 없어서
결국 안정될 때까지 확인해야 합니다. 폴링이 단순하고 더 안전합니다.

사람이 사진을 올리고 바로 결과를 기다리는 작업이 아니라서, 1분 주기여도 문제가 없습니다.

### 동시 실행 방지

렌더링이 CPU 를 오래 씁니다. 두 개가 겹치지 않도록 `output/.watch.lock` 으로 막습니다.
비정상 종료로 잠금이 남으면, 그 프로세스가 죽었는지 확인하고 자동으로 정리합니다.

## ⚠️ 업로드 전에 반드시 할 일

**`review_sheet.jpg` 를 열어 모든 얼굴에 초록 박스가 쳐졌는지 눈으로 확인하세요.**

감지는 100% 정확하지 않습니다. 실측에서 `person` 방식도 45명 중 2명을 놓쳤습니다.
다음 경우 놓칠 수 있습니다.

- 사진 가장자리에서 몸이 크게 잘린 경우
- 다른 사람이나 사물에 거의 가려진 경우
- 아주 작게 찍혀 사람으로 인식되지 않는 경우

**촬영 팁**: 얼굴이 크게 나오는 근접 사진일수록 감지가 잘 되고 영상도 잘 나옵니다.
교실 전체를 멀리서 담은 사진은 감지도 어렵고 숏폼 화면에서 잘 보이지도 않습니다.

### 블러 위치가 빗나가는 경우

감지는 됐는데 가리는 위치가 어긋날 수 있습니다. 카메라를 등지고 앉은 사람은 자세
추정이 뒤통수를 중심으로 잡아서 귀나 턱선이 남습니다. 실제 교실 사진 5장에서 이런
경우가 3장에 있었습니다. 얼굴 자체(눈·코·입)는 카메라 반대편이라 노출되지 않지만,
위 절차대로 `--faces-json` 으로 보완하는 것을 권합니다.

### 직접 블러한 사진을 쓸 때 (`--verify`)

사진을 직접 가려서 올리면 개인정보 면에서 가장 안전하고, 결과물도 깔끔합니다.
사람 눈은 뒤돌아 앉은 학생도 빠뜨리지 않고, 얼굴만 정확히 가릴 수 있으니까요.

이때 `--verify` 를 쓰면 파이프라인이 블러를 새로 적용하지 않고 **검사만** 합니다.
혹시 빠뜨린 얼굴이 있는지 봐 주는 두 번째 눈입니다.

```bash
python make_shorts.py ./photos/수업 -d "..." --verify
```

검수 시트가 세 가지 색으로 표시됩니다.

| 색 | 뜻 | 할 일 |
| --- | --- | --- |
| 초록 | 이미 가려진 영역 | 없음 |
| 빨강 | 선명한 얼굴 | 그 사진을 다시 가리고 재실행 |
| 노랑 | 사람 머리로 추정되나 선명한 영역 | 눈으로 확인 (손·인형인 경우가 많음) |

빨간 박스는 **얼굴 감지기가 직접 얼굴을 찾아낸** 경우입니다. 가려진 얼굴은 얼굴
감지기에 잡히지 않으므로, 빨간 박스가 뜨면 실제로 빠뜨렸을 가능성이 높습니다.
실측에서 가려진 사진 3장은 0·0·1개, 같은 사진의 원본은 4·3·4개가 잡혔습니다.

노란 박스는 자세 추정만으로 잡힌 영역이라 오탐이 섞입니다. 한 장에 몇 개씩 나오는
것은 정상이니 눈으로 훑고 넘어가면 됩니다.

판정 방법과 한계는 `shorts_pipeline/verify.py` 문서화 주석에 적어 두었습니다.
스티커나 이모지로 덮은 얼굴은 가장자리가 날카로워 노란색으로 잘못 뜰 수 있습니다.

### 본인 얼굴은 그대로 두기

선생님 본인이 등장하는 인트로 컷처럼 블러를 넣고 싶지 않은 사진은 파일명을 지정합니다.

```bash
python make_shorts.py ./photos/수업 -d "..." --keep-faces 0_intro.jpg
```

지정한 사진은 블러 없이 그대로 들어가고, 실행 결과에 경고로 다시 알려줍니다.
**학생 사진에는 쓰지 마세요.** 본인이나 명시적으로 동의를 받은 사람만 지정해야 합니다.

### 과잉 차단이 심할 때

기본값은 일부러 넓게 가립니다. 너무 답답하면 `--tight` 로 좁힐 수 있지만, 실측에서
고개를 기울인 학생의 턱이 노출된 적이 있습니다. 쓰신다면 검수 시트 확인이 더 중요해집니다.

놓친 얼굴이 있으면 좌표를 JSON 으로 직접 지정해 다시 실행하세요.

**1단계.** 좌표를 읽을 격자 이미지를 만듭니다. `--blurred` 를 붙이면 현재 가려진 상태
위에 격자가 그려져서, 어디가 아직 노출됐는지 바로 보입니다.

```bash
python scripts/make_grid.py ./photos/수업/4.jpg --blurred
```

**2단계.** 격자 눈금을 보고 가릴 영역의 왼쪽 위 모서리와 크기를 읽어 적습니다.
좌표는 `[x, y, 너비, 높이]` (픽셀, 원본 사진 기준)입니다.

```json
{ "4.jpg": [[1400, 660, 360, 390]] }
```

**3단계.** 그 파일을 넘겨 다시 실행합니다.

```bash
python make_shorts.py ./photos/수업 -d "..." --faces-json faces.json
```

작성 예시는 `examples/faces.example.json` 에 있습니다. 밑줄로 시작하는 키는 메모로
취급해 무시하므로 설명을 적어 둘 수 있습니다.

그 밖에 지켜야 할 것:

- **개인정보**: 학생 사진은 개인정보입니다. 보호자 동의와 학교 보안정책을 먼저 확인하세요.

- **BGM**: 이 파이프라인이 만드는 BGM 은 코드로 직접 합성한 것이라 저작권 문제가 없습니다.
  외부 음원을 쓰려면 CC0 또는 로열티 프리인지 반드시 확인하세요.

## 감지기

| 감지기 | 방식 | 준비 |
| --- | --- | --- |
| `person` | 사람 검출 + 자세 추정으로 머리를 찾음 (권장) | `pip install ultralytics` + `python scripts/download_models.py` |
| `mediapipe` | 얼굴만 감지 | `pip install mediapipe` — 모델 내장 |
| `yunet` | 얼굴만 감지 | `python scripts/download_models.py` |
| `haar` | 얼굴만 감지 | OpenCV 내장, 항상 사용 가능 |

`auto`(기본값)는 `person` 이 준비돼 있으면 그것을, 아니면 얼굴 전용 감지기를 씁니다.

### 왜 얼굴 감지기만으로는 부족한가

실제 교실 사진 5장(사람 45명)으로 측정한 결과입니다.

| 방식 | 찾은 사람 |
| --- | --- |
| `person` (사람 검출 + 자세) | 43 / 45 |
| `mediapipe` (얼굴만) | 13 / 45 |

얼굴 감지기는 **정면을 보고 있는 얼굴**만 찾습니다. 교실에서는 학생들이 고개를 숙이거나,
옆을 보거나, 뒤돌아 앉아 있어서 대부분 놓칩니다. `person` 방식은 사람을 먼저 찾고
자세 추정으로 머리 위치를 잡기 때문에 얼굴이 안 보여도 동작합니다.

`person` 방식은 일부러 과하게 가립니다. 얼굴이 아닌 곳이 가려지는 것은 보기에 아쉬울
뿐이지만, 놓치는 것은 개인정보 노출이라 비용이 전혀 다르기 때문입니다.

> **라이선스 주의**: `person` 방식이 쓰는 YOLOv8(Ultralytics)은 AGPL-3.0 입니다.
> 학교 내부에서 쓰는 데는 문제가 없지만, 이 파이프라인을 외부에 배포할 계획이라면
> 라이선스를 확인하세요.
